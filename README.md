# newscollect

보안 뉴스 RSS를 수집해 사고(incident)별로 중복 없이 정리하는 서비스. 설계는 [DESIGN.md](DESIGN.md) 참고.

## 실행

```bash
export OLLAMA_HOST=10.0.2.2:11434   # 선택: config.toml의 [llm].endpoint보다 우선
python3 -m newscollect              # http://localhost:8000
python3 -m pytest                   # 테스트
```

의존성: fastapi, uvicorn, jinja2, httpx, feedparser, beautifulsoup4, lxml, anthropic, python-dotenv (pytest).

시작할 때 작업 디렉터리의 `.env`를 읽는다(`ANTHROPIC_API_KEY` 등. 이미 설정된 환경 변수가 우선).

## 설정 (`config.toml`)

- 뉴스 소스 추가/삭제/수정: `[[sources]]` 블록을 편집. 매 수집 주기마다 파일을 다시 읽으므로 재시작이 필요 없다. `enabled = false`로 일시 중지.
- LLM 선택: `[llm].provider`
  - `"local"`(기본): Ollama. `endpoint`, `model`, `foreign_model`, `num_ctx`를 쓴다(기존과 동일).
  - `"claude"`: Anthropic API. 키는 `ANTHROPIC_API_KEY`(`.env`), 모델은 `claude_model`(기본 `claude-sonnet-5-5`)로 한국어·외국어 기사 모두 처리, `claude_effort`(`low`~`max`, 기본 `low`)로 생각 깊이를 정한다. 보안 뉴스가 Claude의 `cyber` 안전 분류에 걸려 거부되면 서버 측 대체(fallback)로 같은 요청을 Claude Sonnet 5에서 다시 실행한다. 그래도 거부되면 그 기사는 실패로 두고 다음 주기에 재시도한다(한국어 기사는 규칙 기반 추출로 대체). 키가 없거나 틀리거나 API에 연결할 수 없으면 기사의 시도 횟수를 쓰지 않고 다음 주기로 미룬다. API 사용 요금이 든다.
  - 수집 주기마다 설정을 다시 읽으므로 재시작 없이 바꿀 수 있다.
- LLM: `[llm]`의 `enabled`. `enabled = false`이거나 LLM 호출이 실패하면 규칙 기반 추출로 대체된다.
- 키워드 클라우드: `[wordcloud]`의 `trivial`(아래 '기능' 참고).
- 정부기관·공공기관 목록: `[orgs]`의 `government_list`, `public_list`(CSV 경로, `refs/`에 있음. UTF-8, EUC-KR도 읽음).
- 수집: `[collector]`의 `interval_minutes`, `max_articles_per_run`, `max_age_days`, `database`.

- `[llm].num_ctx`(기본 8192): Ollama로 보내는 컨텍스트 크기. Ollama 기본값(4096)은 긴 한글 기사(글자당 약 1.1토큰)에서 프롬프트가 잘릴 수 있다.

## 영어 등 외국어 소스

`[[sources]]`에 영어 RSS를 추가하면 된다(예: `https://www.bleepingcomputer.com/feed/`, `https://feeds.feedburner.com/TheHackersNews`). 기사 언어는 자동 감지한다.

- 본문은 RSS 요약이 아니라 기사 페이지에서 가져온다(사이트별 본문 영역 + 문단 밀도 기반 자동 탐지, "Related Articles" 등 제거).
- 제목·요약·피해 규모는 **한국어**로 저장하고, 기업·공격 그룹·제품 이름은 **영어 원문 그대로** 둔다(검색도 영어 이름으로 된다). 금액은 단위를 옮긴다($6.3 billion → 63억 달러).
- `[llm].foreign_model`: 비한국어 기사에 쓸 모델. 비워두면 `model`을 쓴다. 이 환경에서 `solar:10.7b`는 영어 기사로 한국어를 쓸 때 한자·일본어가 섞이고 문장이 깨졌고, `exaone3.5:7.8b`는 깨끗한 한국어를 6~15초에 썼다(`gemma3:27b`는 품질은 좋지만 기사당 100초 이상). 수집 시 한국어 기사를 먼저, 그다음 외국어 기사를 처리하므로 모델 교체는 주기당 한 번이다.
- 한국어로 제대로 요약하지 못하면(제목·요약이 한국어가 아님, 기사에 없는 연도·영어 단어 등) 영어 원문을 그대로 저장하지 않고 실패로 두었다가 다음 주기에 다시 시도한다(최대 3회). LLM에 연결이 안 되면 시도 횟수를 소모하지 않고 다음 주기로 미룬다. 규칙 기반 대체는 한국어 기사에만 쓴다.
- 피해 대상/공격자 이름이 기사 본문에 없으면(모델이 "정부 기관"처럼 설명을 쓰거나 이름을 잘못 쓴 경우) 외국어 기사에서는 그 필드만 비우고 저장한다. 한국어 기사에서는 잘못된 이름이 제목·요약에도 쓰였으면 결과를 버린다.
- 이름 보존: 영어 기사의 고유명사(Claude, SysGoRAT 등)는 프롬프트에 목록으로 알려 음차를 막고, `클로이디(Claude)`처럼 괄호 병기된 음차는 영어로 바로잡고, 헤드라인의 이름이 요약에서 빠졌으면 교정 호출을 한 번 더 한다. 그래도 모델이 가끔 이름을 한글로 잘못 옮길 수 있다. 그럴 때는 '요약 다시 생성'을 쓰거나 모델을 바꿔라.
- 서로 다른 언어의 기사가 같은 사고일 수 있다(바이낸스 = Binance). 피해 대상 표기가 한글/영문으로 다르고 날짜가 7일 이내면 `model`(한국어에 강한 쪽)에게 같은 사건인지 물어 합친다. 애매하거나 오류면 합치지 않는다. 이 환경에서 `exaone`은 너무 보수적이어서(같은 사건도 "다르다") 쓰지 않는다. 표본이 작다(같은 사건 1쌍 + 다른 사건 4쌍에서 전부 맞힘).
- 모델이 날짜를 지어내는 경우(2026년 기사에 2021-12-31)에 대비해 사고 발생일은 게시일 기준 6개월 전~게시일 범위만 인정하고, 요약 속 연도는 기사 본문이나 게시 연도에 있어야 한다.

## 기능

- **헤더 고정**: 기사 목록을 스크롤해도 헤더(검색·테마·패널 버튼)는 화면 위에 남는다.
- **테마**: 헤더의 ☀ 라이트 / 🌙 다크 버튼. 선택은 브라우저(localStorage)에 저장되고, 처음에는 OS 설정을 따른다.
- **검색**: 헤더 검색창(`/?q=키워드`). 공백으로 구분한 모든 단어가 제목·요약·공격자·피해·규모·분류 또는 관련 기사 제목에 있어야 한다. `/api/incidents?q=`도 동일.
- **통계 패널**: 목록 페이지 왼쪽 패널에 키워드 클라우드와 수집 기사 수 그래프가 있다(검색 결과 화면에도 표시). 헤더 왼쪽의 패널 아이콘 버튼으로 보이기/숨기기(열려 있으면 강조 표시), 선택은 브라우저에 저장된다. 화면 폭이 900px 미만이면 기본으로 숨겨지고, 열면 목록 위에 겹쳐 뜬다(✕ 닫기, 바깥 클릭, Esc로 닫힘).
- **해시태그**: LLM이 사고를 추출할 때(같은 호출 안에서, 추가 비용 없음) 사고를 대표하는 해시태그 3개를 함께 뽑는다. 피해 대상·공격 유형·업종처럼 서로 다른 측면을 하나씩 담고, 이름은 기사 표기 그대로 쓴다(예: `#미래에셋증권 #개인정보유출 #증권사`). 카드와 상세 화면에 표시되고, 누르면 그 태그로 검색한다(검색은 해시태그도 대상). 같은 사고의 기사가 여럿이면 처음 해시태그를 받은 기사의 것을 쓰고, '요약 다시 생성'은 해시태그도 새로 뽑는다. 규칙 기반 추출이나 이 기능 이전에 저장된 사고에는 해시태그가 없다. `/api/incidents`의 `hashtags` 필드.
- **정부기관·공공기관 태그와 탭**: 피해 대상이 `[orgs].government_list`(KOSIS 기관목록, 2번째 열 기관명)에 있으면 **정부기관**, `[orgs].public_list`(재정경제부 공공기관 지정현황, 1번째 열 기관명)에 있으면 **공공기관** 태그가 붙는다(둘 다 해당하면 둘 다). 이름은 괄호 부분(`(재)`, `(주)`)·재단법인·주식회사·공백을 무시하고 비교하며, 피해 대상 이름에 목록의 기관명이 들어 있어도(`국민건강보험공단 일산병원`) 해당한다. 지방자치단체는 줄임말(`서울시`, `종로구청`)도 인정한다. 목록 위 탭: **전체** / **정부공공**(두 태그 중 하나라도 있는 사고, 검색과 함께 쓸 수 있음). `/api/incidents?tab=gov`도 동일하고 각 사고에 `org_tags`가 들어 있다. 태그는 피해 대상 필드로만 판단하므로 피해 대상이 비어 있는 사고(규칙 기반 추출 등)는 태그가 붙지 않는다. 목록 파일을 새 버전으로 바꾸면 다음 페이지 로드부터 반영된다.
- **키워드 클라우드**: 통계 패널 위쪽. 일간(오늘)·주간(최근 7일)·월간(최근 30일)·연간(최근 1년) 버튼으로 기간을 바꾼다(사고 발생일 기준, 선택은 브라우저에 저장). 사고 제목의 단어와 피해/공격자 이름을 사고당 한 번씩 세고(조사·숫자·흔한 단어 제외), 단어를 누르면 그 단어로 검색한다. `/api/wordcloud?period=week`도 동일.
  - 흔한 키워드 제외: `config.toml`의 `[wordcloud].trivial` 목록(예: `["공격", "해킹", "사이버", "해커"]`). 각 단어 **안에서** 이 키워드를 지우고 남은 부분을 쓴다(`금융권해킹` → `금융권`, `사이버공격` → 빈 문자열이라 제외). 대소문자 무시, 재시작 없이 페이지를 새로 고치면 적용. 피해/공격자 이름은 자르지 않고, 이름 전체가 흔한 키워드뿐일 때만(`해커`) 뺀다. 짧은 키워드는 이름 일부를 지울 수 있으니 주의(`보안` → `금융보안원`이 `금융원`).
- **수집 기사 수 그래프**: 통계 패널에서 키워드 클라우드 아래. 날짜별(최근 30일)·월별(최근 12개월)·연도별(첫 수집 연도부터) 막대 그래프로, 기사를 **수집한 시각**(서버 로컬 시간) 기준으로 센다(사고가 아닌 기사 포함, 수집이 없던 날은 0). 막대에 마우스를 올리거나 키보드로 포커스하면 건수가 보이고, '표로 보기'로 숫자 표를 펼칠 수 있다. `/api/article-stats?unit=day|month|year`도 동일.
- **요약 다시 생성**: 각 사고의 버튼(`POST /incidents/{id}/regenerate`). 원문을 다시 읽고(관련 기사 최대 3건) ① 필드(공격자·피해 등)를 다시 추출하고 ② 요약을 JSON이 아닌 줄글로 따로 쓴다. 결과는 같은 자리에 바로 반영되고(목록·상세 모두) 초록색 안내와 함께 잠깐 강조된다. LLM이 끝내 좋은 요약을 못 쓰고 기존 요약도 망가져 있으면(잘못된 이름·메모체) 기사 본문 첫 문장들로 대체하고 그렇다고 알려준다. 기존 요약이 멀쩡하면 오류를 보여주고 그대로 둔다. 동시에 1건만, 같은 사고는 20초 간격, 최대 약 4분.
- **결과 검증**: 요약은 '~다.'로 끝나는 완전한 문장 2~6개여야 하고(메모체·△목록·반복·한자/영어 섞임 불가), 피해/공격자 이름은 기사 본문에 실제로 있어야 한다(소형 모델이 이름을 잘못 쓰는 경우가 있음). 실패하면 온도를 올려 재시도하고, 끝내 실패하면 수집 시에는 규칙 기반 추출로, 재생성 시에는 오류로 처리한다.

## 엔드포인트

`/` 사고 목록(날짜별, `?q=` 검색) · `/incidents/{id}` 상세 · `/incidents/{id}/card` 카드 조각 · `POST /incidents/{id}/regenerate` · `/api/incidents` JSON · `/api/wordcloud?period=day|week|month|year` · `/api/article-stats?unit=day|month|year` · `/healthz`

주의: 인증이 없으므로 재생성 버튼은 사이트에 접근할 수 있는 누구나 누를 수 있다(LLM 호출을 일으킴). 외부에 공개한다면 리버스 프록시 등으로 `POST` 경로를 제한하라.
